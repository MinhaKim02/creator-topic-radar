# Creator Topic Radar

추천 근거를 확인하면서 숏폼 콘텐츠 소재를 찾는 Agent Skill입니다.

YouTube Shorts, TikTok, Instagram Reels 등을 만드는 크리에이터, 콘텐츠 마케터, 리서처를 위한 리서치 절차입니다. 크리에이터 영상, 최근 사건, 조사 백로그에서 후보를 찾고 관심도·최신성·사실 근거·중복 위험·약 60초 분량의 적합성을 각각 평가합니다.

**버전:** v0.1.0 · **라이선스:** [MIT](LICENSE)

## 바로 사용하기

AI 에이전트가 읽는 Markdown 지침 폴더입니다. 폴더를 읽을 수 있는 에이전트가 필요하며, 실시간 조사에는 웹 출처 접근도 필요합니다. 플랫폼 API나 데이터베이스 연결 도구는 포함되지 않습니다.

1. [저장소](https://github.com/MinhaKim02/creator-topic-radar)에서 전체 `creator-topic-radar` 폴더를 받습니다. GitHub의 **Code → Download ZIP**을 사용할 수 있습니다.
2. 사용하는 환경의 Agent Skills 폴더에 넣고 해당 환경의 인식 절차를 따릅니다. `SKILL.md`와 `references/`를 함께 유지하세요. 자동 로딩을 지원하지 않으면 에이전트에 “이 폴더의 SKILL.md와 연결된 참고 문서를 읽고 따라줘”라고 요청합니다.
3. 시청자, 주제 범위, 조사 기간, 대상 플랫폼, 기존 콘텐츠 목록을 제공하고 후보를 요청합니다.

```text
$creator-topic-radar를 사용해 일상용품 수리에 관심 있는 소비자를 위한
최근 7일 소재를 최대 3개 찾아줘. 크리에이터의 YouTube 영상에서 시작해
실제 사건을 검증하고, 내가 제공한 기존 콘텐츠 목록과 비교해줘.
시간대는 UTC로 해줘. 출처와 미확인 사항을 포함한 후보 목록을 작성해줘.
대본은 작성하지 마.
```

`$creator-topic-radar` 호출 지원 여부는 환경에 따라 다릅니다. 자동 설치·인식 절차는 실행 환경별로 검증하지 않았습니다. 에이전트가 접근할 권한이 있는 자료만 제공하세요. 중요한 맥락이 빠지면 추가로 확인하거나 가정을 밝힙니다. 결과는 별도 요청이 없으면 사용자 언어로 작성합니다.

## 어떤 결과가 나오나요?

각 후보에는 가제, 핵심 질문, 영상이 설명할 내용, 시청자 관련성, 사건·업데이트 날짜, 출처, 다섯 평가 항목, 주의점, 조사 공백, 추천 판단이 포함됩니다. 백로그 기록이 질문을 뒷받침하면 연결할 수 있습니다.

**가상 결과 예시:** 제조사가 5월에 토스터를 출시하고 9월에 교체 부품을 발표했다면, “새 부품 발표는 사용자에게 어떤 변화를 주나?”라는 후보를 만들 수 있습니다.

| 평가 항목 | 판단 예시 |
|---|---|
| 시청자 관심도 | 미평가: 제공된 크리에이터 근거 없음 |
| 최신성 | 과거 사건 + 새로운 전개: 출시일과 부품 발표일을 각각 표시 |
| 사실 근거 | 발표 사실은 뒷받침됨: 부품 제공은 기업 주장이며 수리비 절감을 입증하지 않음 |
| 중복 위험 | 미평가: 기존 콘텐츠 목록 없음 |
| 숏폼 적합성 | 발표 범위에서는 높음: 비용 절감은 추가 근거 필요 |

형식을 설명하기 위한 가상 예시이며 완료된 실제 조사 결과가 아닙니다. [출력 템플릿](references/output-template.md)에서 출처 표기와 선택 후 인계 형식을 확인할 수 있습니다.

기본 종료 지점은 소재 선정입니다. 소재를 선택한 뒤 요청하면 출처·주의점·남은 질문을 담은 사실 중심의 인계 요약을 제공합니다. 대본, 장면 설계, 제작 프롬프트, 발행은 별도 작업입니다.

## 탐색 모드

| 모드 | 출발점 | 조사 내용 |
|---|---|---|
| Creator-first | 크리에이터 영상 | 채널과 접근 가능한 인접 크리에이터, 반복되는 질문, 실제 사건, 사실 출처 |
| Entity-first | 기업·제품·인물·산업·기술 | 구체적인 최근 변화, 시청자 질문, 크리에이터 관심, 근거 |
| User-database-first | 기록·노트·표·아카이브 | 실제 주장, 사건일, 현재 상태, 근거, 시청자 관련성 |

여러 모드를 함께 사용할 수 있습니다. 기업 이름은 탐색 출발점이며, 새로 만든 기록이 반드시 최근 사건인 것은 아닙니다.

## 이 방식으로 조사하는 이유

반복 조사에서는 노출을 사실성으로, 기사 날짜를 사건 날짜로, 다른 기업 이름을 새로운 이야기로 오인할 수 있습니다. 이런 실패 유형을 재사용 가능한 규칙과 검증 사례로 정리했습니다. 임의의 가중치 종합점수 대신 판단 이유를 확인할 수 있게 합니다.

조사 순서는 맥락 확인 → 후보 탐색 → 사건·업데이트 식별 → 관심과 사실의 분리 조사 → 중복·분량 적합성 평가 → 근거와 함께 추천입니다.

| 판단 | 핵심 규칙 |
|---|---|
| 크리에이터 관심 | 영상 나이, 채널 영향력, 수치 확인 경로를 비교합니다. 막 올라온 영상은 성과 판단이 어려우면 초기 신호로 표시합니다. |
| 최신성 | 사건·발행·기록·주장·실질적 업데이트 날짜를 구분합니다. 과거 시점 조사에는 그때까지 확인 가능한 근거를 사용합니다. |
| 사실 근거 | 주장에 맞는 직접 출처를 확인하고 사실·기업 주장·보도·해석·예측을 구분합니다. 중요한 충돌을 밝힙니다. |
| 중복 | 이름보다 질문·원리·결론·시청자가 얻을 이해를 비교합니다. 기존 콘텐츠 및 후보끼리 비교하고 확인 범위를 밝힙니다. |
| 숏폼 적합성 | 하나의 질문과 필수 주의점을 유지합니다. 60초에 맞추려고 사실을 과장하지 않고 범위를 좁힙니다. |

공식 근거가 시청자 관심까지 입증하지는 않으며, 크리에이터 인기가 주장을 검증해주지는 않습니다. 비즈니스·투자 관점은 근거 있는 연결이 있을 때 사용합니다.

## 한계와 검증

검색 범위, 플랫폼 수치, 같은 영상 나이의 비교값, 추천 영상 구조 접근은 도구에 따라 다릅니다. 수치가 없다고 관심이 없다고 판단하지 않으며, 기존 콘텐츠가 없으면 중복 위험은 미평가입니다. 오프라인에서는 제공된 근거를 평가할 수 있지만 이후 현실의 변화를 확인할 수는 없습니다.

근거가 부족하면 요청 수보다 적게 추천하거나 추천하지 않습니다. 바이럴 성과, 사실 정확성, 조회수, 조사 시간 절감을 보장하지 않습니다. 여러 실행 환경의 호환성을 폭넓게 검증하지 않았습니다.

[검증 사례](tests/cases.md)는 가상 입력과 검토 절차이며 벤치마크 결과가 아닙니다. 실제로 의존하기 전에 사용하는 환경에서 검증하세요.

영상 나이를 고려한 비교, 여러 플랫폼의 신호, 중복 검사 강화, 추천 채택·거절 기록을 활용한 반복 평가와 데이터셋·벤치마크를 개선 후보로 둡니다. 완료된 성과가 아닌 향후 방향입니다.
